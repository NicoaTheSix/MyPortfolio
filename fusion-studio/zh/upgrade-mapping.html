Docs/Tactic 搬移與衝突
本頁章節
明確指定目標清單個別檢視及編輯目標逐欄審核衝突避免沿用過期決策保存與交換程式流程與驗證

一對多 Tactic 搬移與欄位衝突審核#

開啟 Navigator → Review and upgrade layer…（審閱並升版圖層），載入同領域目標，在「註記搬移決策」選擇來源列。完整技術審核及並排內容／編輯仍可使用。

明確指定目標清單#

按 Edit mapping targets…（編輯映射目標），每列選一個目標技術與有效 Tactic，或 All tactics。透過新增／移除目標，把同一來源範圍搬到多個 Tactic，也能指定不同目標技術；技術選單可輸入搜尋。儲存只更新記憶體草稿並選擇 Copy，取消保留原清單。

Copy 必須有 1～100 個目標。重複的技術／Tactic、未指定或已移除的 Tactic、失效 ID、空清單都會拒絕。同一來源列對同一目標技術，All tactics 不得與個別 Tactic 並存。只要子集合時請逐列指定；整個來源不要搬移則選 Drop。展開後最多 20,000 筆註記貢獻。

搬移表會顯示目標數；多目標列鎖定原本的主要技術／Tactic 欄，改由目標清單編輯。只剩單一目標時，原欄位仍可編輯，既有目標註記修改會跟隨重新映射。Drop 會保留草稿供改回 Copy，但不輸出該來源的註記或選取。

個別檢視及編輯目標#

選擇來源映射列；有多個目標時，比較區的目標選單決定右側顯示哪一個，以及「編輯目標註記」修改哪一個。各目標可分別設定 Comment、Score、Color、Enabled、Links、Metadata，修改一個不會改到其他目標。編輯器仍鎖定目標 ID／範圍，欲變更請回目標清單。

來源選取只搬到明確指定的範圍。例如目標有三個 Tactic，把已選來源搬到 Execution、Initial Access 後，只選這兩格，Persistence 保持未選。原本未選的註記也不會自動選取。Enabled 與選取互相獨立。All tactics 代表明確指定該目標所有有效 Tactic；家族／跨 Tactic 選取偏好不會額外擴大映射。

逐欄審核衝突#

處理有效 Copy／Drop 後，按 Review migration conflicts…（審核搬移衝突）。背景計畫會納入所有來源列及獨立目標草稿，包含被篩選隱藏的項目。尚未完成來源審核時也能預覽，但最後建立仍須全部來源與技術確認。

同一目標技術與範圍的多筆資料，若對純量／擴充欄位提供不同明確值，就會列為衝突，例如 Score、Color、Enabled 或匯入的擴充物件。缺少某欄代表未提供值。全域預設列與個別 Tactic 覆寫仍屬不同 Navigator 範圍，不會自動視為同格衝突。

查看每欄來源標籤與完整候選值，選擇：

方式 效果
某個來源候選 使用該來源的完整原值。
自訂 JSON 值 輸入有限、合法且符合欄位型別的 JSON，例如分數 6.75、啟用 true、顏色 "#aabbcc"。
清除欄位 從合併結果移除該欄位。

逐列勾「已審閱」後儲存。缺少決策、未勾選、無效 JSON、NaN／Infinity 或不合法型別都會拒絕。JSON null 是值，不等於移除；移除分數／顏色請選「清除欄位」。更改選擇或值會清除該列已審。沒有衝突時，介面會明確顯示空狀態。

不同且非空的 Comment 各保留一次，後續內容附來源標籤；三筆以上來源出現相同註解也不重複。Links／Metadata 依完整項目去重，保留擴充屬性。內部選取標記在搬移時去除，匯出再依真正選取狀態產生，每列最多一次。相容純量直接保留，不須開啟衝突介面。

避免沿用過期決策#

修改映射或註記會使目前衝突決策失效。後端另以該目標完整來源列及來源識別的 SHA-256 指紋綁定決策，直接以 API 提交也會拒絕過期、無關、重複或未審的選擇。獨立目標草稿的變更也包含在檢查內。

重新開啟未變更的衝突時，會還原已存選擇與勾選；取消保留原決策。候選改變後請重新審核。解決欄位衝突不會自動確認來源映射或技術。來源驗證、候選值驗證與最終決策驗證全部完成後，才安裝新文件；失敗或取消不改來源，也不產生部分結果。

保存與交換#

結果的 Studio migration_archives 保留完整來源；x_ttp_studio_upgrade.review_schema 改為 2。來源決策保留舊欄位，另記錄正規化 targets 與各目標註記補丁；conflict_resolutions 保存目標／範圍／欄位、候選指紋、明確動作及生效值。舊版單目標輸入與既存審核記錄仍可讀取。

Studio 儲存／重開及 session 復原保留註記、部分選取、完整決策與來源封存。Navigator JSON 保留展開後的標準技術註記、選取擴充及審核來源；其他 Navigator 程式可能忽略 Studio 的審核擴充，完整來源封存請保存 Studio JSON。尚未提交的升級視窗草稿會在重新載入目標或關閉時清除，請在建立結果後保存文件。

程式流程與驗證#

運作前先明示記憶體輸入／無輸出檔案；載入與 Save／Export 另列絕對檔案路徑。Upgrade 1/3 比較快照 → 2/3 驗證／展開目標、驗證每個候選並找出衝突 → 3/3 建立完整已審結果。目標清單顯示 Upgrade targets 1/2 → 2/2，欄位決策顯示 Upgrade conflicts 1/2 → 2/2；註記編輯維持兩階段進度。預覽與編輯視窗不直接寫檔。

於專案根目錄安裝相依套件後執行：

powershell
$env:QT_QPA_PLATFORM = 'offscreen'
& '.\.venv\Scripts\python.exe' -B '.\audit_upgrade_mapping.py'

七階段先列絕對輸入／輸出目錄，再測三 Tactic 快照 → 明確展開與部分選取 → 欄位／過期決策及三來源去重 → 原生目標／分支編輯與取消 → 原生決策／JSON／重開／失效及雙語控制 → Studio／session／Navigator 與舊格式相容 → 發布 artifacts/upgrade-mapping/audit.json。截圖包含 mapping-en.png、mapping-zh.png、conflicts-en.png；快取與生成檔案均留在該產物目錄，已登錄至 scripts/audit_linux.py。最後摘要及理由編輯已完成，詳見操作手冊。
