Fusion Studio 產品定位#

版本：1.0 · 更新日期：2026-10-24（Asia/Taipei） · 作者／維護者：Nicoa Wu

本文件作為產品方向、功能取捨、使用說明與推廣內容的共同基準。免費開源及原始開發目的已由作者確認；核心客群、問題普遍性與採用成效仍需透過實際使用者驗證。本文依目前專案 README、操作手冊與 LICENSE 整理，未在本次重跑應用程式或進行市場調查。

1. 產品定位摘要#

Fusion Studio 是免費、開源、以 TTP 為核心的威脅研究工作區，協助資安分析者整理威脅情報、記錄分析判斷，並保存與匯出可持續更新的研究成果。

英文定位：

Fusion Studio is a free, open-source workspace for TTP-driven threat research. It helps security analysts organize threat knowledge, document analytical judgments, and save or export their research.

要素 定位
產品類別 資安威脅研究與分析成果整理的桌面工作區
核心使用者 需要整理 TTP、撰寫威脅研究報告的資安分析者、個人研究者與小型 CTI 團隊
主要任務 將查閱到的威脅資料，整理成有技術選取、註解及來源連結的研究文件
核心價值 讓技術資料、選取範圍與分析判斷可以一起保存、重開、更新與交付
主要研究材料 MITRE ATT&CK、ATLAS 與 CAR；各資料維持其原始語意與適用範圍
取得與使用原則 免費使用、開源提供；目前原創專案程式採 MIT 授權，完整條款見 LICENSE
目前產品階段 持續開發與測試，功能與支援範圍以當次版本文件為準

對外介紹時，先說明使用者能完成的研究任務，再介紹框架、矩陣及匯出格式。免費開源是產品的基本原則；研究工作的實際價值是推廣主軸。

2. 已確認的產品原則#

2.1 免費與開源#

  • 使用者不需要付費即可使用本專案提供的功能。
  • 以開源專案形式提供原始碼，方便理解、檢視、修改及參與改善；實際授權條件依 LICENSE。
  • 文件與推廣採「使用者」作為主要稱呼，不以購買或訂閱作為使用流程的前提。
  • 第三方元件、圖示來源與上游資料保留各自的授權及標示；免費開源的產品定位不把所有第三方內容改成 MIT。
  • 免費提供不等於承諾企業級服務時效或完成所有客製需求；支援方式與開發優先序依專案實際公告。

本文件不規劃收費方案、付費功能分級或訂閱服務，也不修改現有 LICENSE。

2.2 以研究工作為中心#

作者已確認，最初開發目的是「整理威脅情報、TTP 與研究報告」。功能規劃因此優先支援從查閱到交付的連續流程：

查閱來源 → 界定研究範圍 → 選取 TTP → 記錄理由與來源連結 → 分析比較 → 保存／匯出 → 後續更新。

2.3 清楚區分資料與分析判斷#

上游資料中的描述與關聯、使用者自行填寫的註解與評分，以及實際測試證據，應可辨識其來源。選取技術代表納入研究範圍；評分與顏色的意義由研究者定義。兩者本身均不證明攻擊已發生、偵測已部署或控制措施有效。

3. 核心使用者#

3.1 第一優先：威脅研究與 CTI 分析者#

項目 描述
典型角色 個人資安研究者、CTI 分析師、兼任威脅研究的資安人員，以及以檔案交換成果的小型研究團隊
既有能力 能閱讀基本資安資料，理解或正在學習以戰術、技術與子技術描述行為
常見任務 研究攻擊組織、惡意軟體、攻擊活動或事件，將相關 TTP 整理成研究清單與報告素材
交付對象 自己、同事、主管、研究合作對象或顧問服務對象
需要保存的內容 選取範圍、選取理由、研究註解、參考連結、使用資料版本，以及供後續整理的輸出
開啟產品的時機 已有研究題目，需要從大量技術與參考資料中整理一份自己的研究成果

核心客群以工作任務定義，無須先具備特定職稱。小型團隊的適用情境是分工研究與交換檔案；目前定位不承諾多人即時共同編輯。

3.2 次要使用者#

使用者 適合的工作 與核心定位的關係
偵測工程師與藍隊研究人員 查閱偵測策略、資料來源與 CAR，整理規則研究及資料需求 將研究成果作為後續偵測開發的輸入
紫隊與演練規劃人員 規劃技術範圍、記錄目標與證據連結、整理演練結果 沿用相同研究文件與矩陣工作流程
AI 安全研究者 查閱 ATLAS 技術、緩解措施與案例，整理 AI 威脅情境 將同一工作流程應用於 AI 安全研究
資安顧問與安全架構師 整理技術、分析註解與評估資料，準備交付圖表 使用研究成果支援顧問報告及討論
教師、學生與自學者 建立主題式技術清單、學習筆記與案例教材 使用研究工作區協助理解與表達

早期推廣優先驗證第一優先客群，次要情境可作教學案例。上述客群排序是產品假設，尚非市場採用結果。

4. 要解決的問題#

下列問題由作者開發目的與目前功能歸納；外部使用者是否同樣遇到、發生頻率及嚴重程度，需在訪談與實作中確認。

問題 工作上的影響 Fusion Studio 的處理方式
資料查閱與研究整理分散 看過許多網頁與資料後，仍需重新整理本次研究涉及哪些技術 在工作區瀏覽參考資料，將技術與 CAR 研究內容明確納入文件
技術清單缺少選取理由 只剩 ID 或勾選結果，之後難以理解當時的判斷 使用註解、連結與適用的 Metadata 留下研究脈絡
多個題目容易混在一起 不同組織、事件或研究用途的技術與筆記互相干擾 使用獨立文件與圖層，維持各自的研究狀態
研究難以接續更新 下一次工作仍需重建選取範圍與註記 保存完整 Studio JSON，重新開啟後持續編輯
從研究轉成報告素材需要重整 相同內容要再製作成表格、矩陣或交換檔案 依用途匯出 CSV、SVG、Excel 或 Navigator 圖層
資料版本更新影響既有研究 舊技術、註解與新版資料之間需要逐項檢視 使用已支援的版本比較與審核式遷移流程

目前工作方式可能包含瀏覽器、試算表、筆記與圖層工具。這些是待訪談核對的替代流程，不代表已研究所有競品或證實本產品更快。

6. 適合的應用情境#

情境 A：攻擊組織、軟體或活動的 TTP 研究#

**觸發需求：**分析者需要針對一個研究對象，整理其資料中已記載的相關技術及自己的判斷。

**工作流程：**建立獨立文件 → 查閱組織／軟體／活動與關聯技術 → 加入研究範圍 → 閱讀技術說明與案例 → 記錄理由、來源及待查項目 → 保存與匯出。

**適合產出：**研究技術清單、帶註解的矩陣、報告附表與可重開研究文件。

**範圍說明：**資料中的既有關聯不代表特定組織在每次事件都使用全部技術；本次事件適用性由分析者確認。

情境 B：事件調查結果的技術化整理#

**觸發需求：**調查者已有事件觀察或證據，需要以一致的技術語言整理研究摘要。

**工作流程：**建立事件研究文件 → 人工對照觀察與 TTP → 加上證據連結、判斷理由及不確定性 → 整理矩陣與清單 → 交付報告素材。

**適合產出：**事件 TTP 摘要、分析筆記與後續討論材料。

**範圍說明：**證據需由其他調查流程取得；目前不承諾自動匯入事件日誌、擷取 IOC、鑑識或自動歸因。

情境 C：偵測內容與資料需求研究#

**觸發需求：**偵測工程師要了解研究技術有哪些策略、資料來源或 CAR 分析可供參考。

**工作流程：**選定技術 → 查閱偵測策略與資料關聯 → 閱讀相關 CAR 內容、Data Model 或 Sensors → 納入適合的研究項目 → 記錄資料需求與待測試事項 → 交付開發待辦。

**適合產出：**偵測研究清單、參考查詢與實作資料、待驗證資料需求。

**範圍說明：**CAR 選取與 TTP 選取各自獨立。感測器與分析的候選關聯不證明資料完整或偵測有效；實際部署及測試需另行完成。

情境 D：紫隊演練的範圍與結果整理#

**觸發需求：**演練前要界定測試技術，演練後要保留觀察與結果。

**工作流程：**選取本次技術 → 以註解與 Metadata 記錄目標、負責人及證據連結 → 由外部工具完成演練 → 更新研究內容 → 在相容範圍內比較圖層與整理圖表。

**適合產出：**演練技術範圍、觀察筆記、待改善清單與討論矩陣。

**範圍說明：**演練動作、日誌及驗證結果由外部流程提供；分數與顏色採用的規則需自行說明。

情境 E：AI 系統的威脅研究#

**觸發需求：**研究者希望整理與某個 AI 系統有關的 ATLAS 技術、案例及緩解思路。

**工作流程：**界定研究系統與假設 → 查閱 ATLAS 技術、案例與緩解措施 → 選取與題目相關內容 → 寫下適用理由與待驗證假設 → 保存並輸出適用格式。

**適合產出：**AI 威脅研究清單、案例筆記及安全審查討論素材。

**範圍說明：**ATLAS、ATT&CK 與 CAR 在同一工作區提供參考，不代表三者存在通用、自動或完整的對應關係；各匯出與分析功能須依框架支援範圍使用。

情境 F：研究維護、教學與成果展示#

**觸發需求：**研究需要配合資料版本更新，或將既有內容轉成易於解說的教材與圖表。

**工作流程：**開啟既有文件 → 檢視資料版本及研究內容 → 使用適用的版本比較與遷移流程 → 更新註解 → 匯出矩陣或表格供教材、簡報與報告使用。

**適合產出：**研究更新紀錄、課程技術清單、SVG 矩陣、Excel 分析表與可交換的研究檔案。

**範圍說明：**跨版本及跨圖層比較有相容條件；完整教案、簡報敘事與研究結論仍需作者編寫。

7. 研究成果與檔案的角色#

格式／內容 適合用途 重要範圍
Studio JSON 保存並重開完整研究工作內容 保存時需包含所需內容類型；完整保存與部分輸出有別
Navigator JSON 交換目前支援的 ATT&CK 圖層與註記 依圖層、資料版本及框架限制，不保存完整 CAR 研究狀態
CSV 將選取內容及對應欄位交給表格流程 交換報表用途，不等同完整可重開文件
SVG 將支援的技術矩陣放進簡報與報告 視覺呈現用途，不保存全部研究狀態
Excel 檢視支援的矩陣、技術與圖層資料 依所選匯出功能而定，不取代完整 Studio 保存
原始 STIX／TAXII JSON 複製 查閱或引用所選來源物件 與保存使用者研究文件是不同操作

對外可說「支援研究整理與報告素材輸出」。目前不承諾自動完成整份敘事型研究報告。

9. 功能取捨原則#

後續功能優先考慮下列問題：

  1. 是否讓核心使用者更容易完成一份真實的威脅研究？
  2. 是否讓技術選取、註解與來源連結更清楚，並在保存、重開及交換時保留？
  3. 是否改善資料版本相容性、匯出可信度或研究接續能力？
  4. 是否降低首次安裝、第一次完成研究與後續更新的阻礙？
  5. 是否符合免費開源原則，且能以現有維護能力持續支援？

優先方向包括研究入口、註解與來源脈絡、保存與交換、清楚的匯出用途、範例與手冊。新平台、更多資料來源或自動化功能應說明它們改善哪個核心任務，再排入規劃。本節為方向準則，不是已排定的開發承諾。

10. 定位驗證與成功判斷#

目前已確認的是作者自己的需求及免費開源意願。外部使用者是否需要本產品、是否願意持續使用，以及相較既有工作方式的實際效益，尚需驗證。

建議以少量願意實作的威脅研究者開始，讓每人帶入自己的題目，完成以下任務：

  1. 找到研究對象或技術，建立一份獨立文件。
  2. 選取相關 TTP，至少記錄一項選取理由及可回查的來源。
  3. 保存、關閉並重新開啟，確認內容保留。
  4. 匯出一種自己會使用的報告素材。
  5. 在後續研究中再次開啟、修改或更新該文件。

觀察成功啟動、任務完成、需要協助的步驟、保存與重開正確性、匯出是否可用，以及是否用真實題目再次使用。訪談應詢問原本流程、具體卡點與成果用途，並同時記錄不需要本工具的原因。

Star、下載與影片觀看可作觸及參考；持續完成研究與再次使用更接近產品價值。時間改善需在明確任務及對照流程下量測後，才作對外主張。回饋以自願提供為原則，本文件不要求新增使用遙測。
