Fusion Studio#

A free, open-source workspace for TTP-driven threat research.

Fusion Studio helps security analysts turn threat knowledge into organized research. Explore MITRE ATT&CK®, ATLAS and CAR reference content, select the techniques relevant to your topic, record your analytical notes, and save or export your work for further analysis and reporting.

Built for CTI analysts, independent security researchers and small research teams, Fusion Studio brings reference browsing, technique selection and research notes into a VS Code-inspired desktop workspace. The interface and operating manuals support English and Traditional Chinese.

Quick start#

Windows PowerShell: install Python 3.11 first, then run the following from a writable project folder. Initial dependency and dataset downloads need internet access; cached-data browsing works offline. For Linux or WSL2, follow the dedicated installation steps.

1. Get the source. Clone it, or select Code → Download ZIP on the repository page, extract it and open PowerShell in the extracted folder if Git is unavailable.

powershell
git clone https://github.com/NicoaTheSix/MITREATTACK_SIMULATOR.git
Set-Location -LiteralPath '.\MITREATTACK_SIMULATOR'

2. Create the local Python environment and install dependencies. No environment activation is required.

powershell
Write-Output ('Input requirements: ' + (Resolve-Path '.\requirements.txt').Path)
Write-Output ('Output Python environment: ' + (Join-Path (Get-Location).Path '.venv'))
py -3.11 -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r '.\requirements.txt'
& '.\.venv\Scripts\python.exe' -m pip check

3. Prepare local datasets. On a fresh checkout, use the scripts below to prepare ATT&CK, ATLAS and CAR. Skip a downloader when your copy already contains that dataset and its valid source manifest/pointer. Each script reports its source, absolute output paths and stage progress; wait for successful completion before launching.

powershell
& '.\.venv\Scripts\python.exe' -B '.\scripts\download_attack_data.py'
& '.\.venv\Scripts\python.exe' -B '.\scripts\download_atlas.py'
& '.\.venv\Scripts\python.exe' -B '.\scripts\download_car.py'

4. Launch Fusion Studio. Run this command again for later launches, keeping the terminal open while using the application.

powershell
& '.\.venv\Scripts\python.exe' -B '.\main.py'

After setup, you can optionally register the fusionstudio Windows command or the Linux/Bash/Zsh command. These commands launch the desktop application. For Python-path alternatives and common installation failures, see Installation.

Your first research document#

  1. Wait for dataset loading to complete, then choose File → New File (Ctrl+N) to start a separate document. A normal launch may restore previous work.
  2. In the ATT&CK TTP sidebar, search for T1059.001 (PowerShell) and check it to include it. Add T1082 or another technique relevant to your topic.
  3. Review the included techniques in Workplace. A single click highlights a row; use its right-click menu to view information or edit a TTP annotation.
  4. Choose File → Save As… (Ctrl+Shift+S), keep all content types checked, and save a Studio JSON file. Close that document and use File → Open Studio JSON… (Ctrl+O) to continue it later.
  5. Use Export JSON / CSV… to create a CSV for reading or sharing. CSV and Navigator JSON are exchange formats; keep the Studio JSON for complete editable research.

Checking a technique includes it in your research document; it does not execute the behavior or establish detection coverage. The operating manuals cover matrix selection, annotations, ATLAS, CAR and supported export formats.

What you can do#

  • Research threats: explore groups, software, campaigns, techniques and procedure examples, then assemble the TTPs relevant to your research topic.
  • Keep your reasoning with your research: add technique comments, reference links and metadata, and use supported layer scores and colors to express your own analysis.
  • Explore detection and AI security references: browse CAR analytics, data models and sensors, alongside ATLAS techniques, mitigations and case studies. ATT&CK and ATLAS selections remain independent; CAR analytics are separate research entries in the Workplace.
  • Continue and deliver your work: save and reopen research documents, compare supported ATT&CK layers and dataset versions, and export lists, matrices or tables for reports and presentations.

Typical use cases#

  • Build a TTP research profile for a threat actor, malware family or campaign.
  • Organize analyst-mapped techniques, notes and evidence links for an incident research summary.
  • Prepare detection research or purple-team exercise scope and record items that need testing.
  • Collect ATLAS references for an AI security study, or create technique-based teaching materials.

Research workflow: Explore → Select TTPs → Add notes and references → Compare → Save and export → Revisit and update.

Use Studio JSON to preserve editable research, including the content types selected when saving. Use Navigator JSON for supported ATT&CK layer exchange, CSV for tabular exchange, and SVG / Excel for supported matrix and analysis outputs. Formats preserve different content; see the operating manuals for details.

Installation#

The steps immediately below cover Windows. For native Linux or WSL2/WSLg, use Linux / WSL2 Installation.

Requirements#

Use Windows PowerShell and Python 3.11, the Python version used to verify this project. Install Python from python.org if needed. Git is optional if you download the source as a ZIP. First-time package installation and ATT&CK downloads require an internet connection.

The project can be placed in any writable folder on your computer. In this README, <project-root> means the absolute path of that folder. Run the commands below from the folder containing main.py and requirements.txt; all executable commands use paths relative to it.

1. Get the Project#

Clone the repository into your chosen parent directory:

powershell
git clone https://github.com/NicoaTheSix/MITREATTACK_SIMULATOR.git
Set-Location -LiteralPath '.\MITREATTACK_SIMULATOR'

Alternatively, download Code → Download ZIP from the repository, extract it, and open PowerShell in the extracted project folder. If you already received an extracted source folder, start there.

2. Create a Virtual Environment and Install Dependencies#

Create a new .venv inside your own copy of the project:

powershell
Write-Output ('Output directory: ' + (Join-Path (Get-Location).Path '.venv'))
py -3.11 -m venv .venv
Write-Output ('Input file: ' + (Resolve-Path '.\requirements.txt').Path)
Write-Output ('Output directory: ' + (Join-Path (Resolve-Path '.\.venv').Path 'Lib\site-packages'))
& '.\.venv\Scripts\python.exe' -m pip install -r '.\requirements.txt'
& '.\.venv\Scripts\python.exe' -m pip check

If py is unavailable, check python --version. When it reports Python 3.11, use python -m venv .venv instead of py -3.11 -m venv .venv. The dependency installation and check must finish successfully before proceeding. Each computer should create its own virtual environment.

3. Download ATT&CK Data#

For a fresh checkout, download the latest official stable ATT&CK snapshot:

powershell
& '.\.venv\Scripts\python.exe' -B '.\scripts\download_attack_data.py'

The script prints resolved absolute paths and progress, downloads Enterprise/Mobile/ICS bundles, validates them, and writes the snapshot and latest.json inside this project's data\attack directory. HTTPS access to api.github.com and raw.githubusercontent.com is required. Wait for 5/5 Publish — Complete before starting the interface. You can skip this step if your project copy already includes a valid snapshot and its pointer. See scripts/README.md for the download workflow and error handling.

4. Start the Application#

powershell
& '.\.venv\Scripts\python.exe' -B '.\main.py'

Wait for catalog-loading progress to finish. Fusion Studio opens with a new Enterprise document. Select TTPs, or right-click the filename to choose Mobile or ICS. Keep the terminal open while the application runs. Export documents you want to retain before using File → Exit / Ctrl+Q.

For later launches, open PowerShell in the same project folder and run only the command in this step. Cached-data startup and local browsing work offline.

Optional: Activate the Environment or Open an Editor#

The commands above use the environment's Python directly. To activate it instead:

powershell
& '.\.venv\Scripts\Activate.ps1'
python -B '.\main.py'

After closing the application, deactivate leaves the environment. If PowerShell blocks Activate.ps1, use the direct .venv\Scripts\python.exe command in step 4.

To inspect the source in VS Code, use File → Open Folder and select your project folder, or run code . if that command is installed. Select your project's .venv\Scripts\python.exe as the Python interpreter.

Troubleshooting#

  • Missing Python or packages: verify Python 3.11 is installed and repeat step 2 using your project's .venv interpreter.

  • Missing or invalid ATT&CK data: repeat step 3 and inspect the terminal/Output messages. Startup uses data\attack\active.json when present, otherwise data\attack\latest.json, and validates the referenced local bundles.

  • No visible window after an offscreen audit: clear that PowerShell session's preview setting before launching again:

    powershell
    Remove-Item Env:QT_QPA_PLATFORM -ErrorAction SilentlyContinue

Startup displays absolute input paths before reading files and reports Resolve → Read → Index → Tree progress. Ordinary startup and local browsing use cached data without network requests; Studio saves and automatic workspace checkpoints preserve document work locally.

Linux / WSL2 Installation#

Use a Linux desktop session, or WSL2 with WSLg for visible windows. WSLg requires Windows 11 or Windows 10 build 19044 or newer; check wsl --list --verbose from Windows and choose a distribution marked version 2. Verified on 2026-10-20 with Kali GNU/Linux 2026.2 x86_64 on WSL2, native Python 3.14.7 and PySide6 6.12.0. A successful WSLg test does not establish support for every distribution, CPU architecture or desktop environment. See Microsoft's WSL GUI guide and Qt for Linux requirements.

The Linux/WSL2 test report (繁體中文) records 31 audit programs passing after targeted repairs/rechecks, 30 real WSLg Manual feature/language cases, and 70 Windows custom-source regression checks. Startup passed through xcb, Wayland and the automatic Qt backend. The full feature suite mainly used native Linux Qt offscreen; real xcb coverage included Manual/file-picker and custom-source workflows, while Wayland coverage was startup only. Initial failures and subsequent rechecks are retained in the verification data. Other distributions/desktops, full Wayland workflows and external website opening in a configured browser remain unverified.

1. Install Linux System Dependencies#

Run these commands inside the Linux terminal, not Windows PowerShell. The following package names were exercised on Kali; Ubuntu/Debian versions can use different GLib package names (libglib2.0-0 on releases before the t64 transition).

bash
printf 'Input package sources: /etc/apt/sources.list and /etc/apt/sources.list.d\nOutput package directories: /usr, /var/lib/apt/lists, /var/cache/apt\n'
sudo apt-get update
sudo apt-get install -y --no-install-recommends \
  python3 python3-venv libegl1 libopengl0 libglib2.0-0t64 \
  libxkbcommon-x11-0 libxcb-cursor0 libxcb-icccm4 libxcb-keysyms1 \
  libxcb-image0 libxcb-render-util0 fonts-noto-cjk

The XCB libraries are needed even when PySide6's Python installation succeeds. Missing libxcb-icccm.so.4 or libxcb-keysyms.so.1 can produce the generic “Could not load the Qt platform plugin xcb” message. CJK fonts supply Traditional Chinese glyphs on Linux.

2. Create a Separate Linux Checkout and Environment#

Prefer a folder under the Linux home directory so Linux's filesystem and filename case sensitivity are exercised. Clone the project there, or copy an existing source tree while excluding Windows .venv, private settings and recovery files. Each operating system needs its own environment; do not copy Windows .venv into Linux. The Windows requirements-lock.txt is an environment snapshot containing Windows-only dependencies; install from requirements.txt here.

bash
git clone https://github.com/NicoaTheSix/MITREATTACK_SIMULATOR.git "$HOME/MITREATTACK_SIMULATOR"
cd "$HOME/MITREATTACK_SIMULATOR"
printf 'Input requirements: %s/requirements.txt\nOutput environment: %s/.venv\n' "$PWD" "$PWD"
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check

If you intentionally share a source folder with Windows through /mnt/d/..., name the Linux environment .venv-linux and substitute .venv-linux/bin/python in the commands. The Linux launcher detects it when .venv/bin/python is absent. Keep tests and personal workspaces in separate copies because preferences and recovery files are stored with the project.

3. Prepare ATT&CK Data and Launch#

If your copy does not already contain a valid cached snapshot and data/attack/active.json or latest.json, download the official data first:

bash
.venv/bin/python -B scripts/download_attack_data.py

Launch the native Linux application from any working directory by invoking the launcher with its path:

bash
bash "$HOME/MITREATTACK_SIMULATOR/start-fusionstudio.sh"

Use bash start-fusionstudio.sh --check from the project folder to check dependencies without opening a window. bash start-fusionstudio.sh --no-session starts a workspace without automatic recovery, which is useful for isolated testing. Main-program flags such as --data-dir and --smoke-test are forwarded unchanged. Advanced users can select another native Linux environment with FUSIONSTUDIO_PYTHON=/absolute/path/to/venv/bin/python.

The launcher resolves its own location, prints absolute program/Python/requirements inputs, then reports 1/3 environment → 2/3 imports → 3/3 launch. main.py prints the resolved data inputs and application outputs before processing; settings and session code announce their own paths. The launcher keeps diagnostics in the current terminal and runs in the foreground. It does not download packages, edit shell profiles or set a Qt backend. Windows-only taskbar integration is skipped on Linux. To launch directly, use .venv/bin/python -B main.py.

4. Set Up fusionstudio Once for Bash and Zsh#

After completing the Linux installation, run this inside Linux, from the downloaded project folder:

bash
bash setup-fusionstudio.sh

Close and reopen your Bash or Zsh terminal. From any directory, run:

bash
fusionstudio

For the current terminal without reopening it, run export PATH="$HOME/.local/bin:$PATH" once. fusionstudio --check checks dependencies without opening a window; fusionstudio --no-session disables recovery for an isolated workspace. Application flags are forwarded unchanged. The command runs in the foreground, so keep its terminal open while using the app.

Setup installs only the current user's ~/.local/bin/fusionstudio, with no sudo or package downloads. It adds one marked, duplicate-safe PATH block to .profile, .bashrc, .zprofile and .zshrc; an existing Bash login profile is also covered. An exported absolute ZDOTDIR is respected for Zsh profiles. Existing content is retained, and changed existing profiles receive timestamped .fusionstudio-backup-... copies before editing. Repeating setup does not duplicate blocks or backups; rerunning it after moving the project updates the managed command to the new location. Keep the project folder and Linux environment available. Other shells such as Fish require their own PATH configuration.

To migrate an existing Linux setup, run bash setup-fusionstudio.sh from the updated project. After fusionstudio --check succeeds, setup removes only the intact former ~/.local/bin/ttpselecter wrapper generated by this project. It reuses existing marked PATH blocks and preserves old backups. Unrelated old-named commands and symlinks are retained; edited managed wrappers stop preflight without changes. The former root setup-ttpselecter.sh / start-ttpselecter.sh entries are removed. Clear an existing shell command cache with hash -r (Bash) or rehash (Zsh), or reopen the terminal. The environment override is now FUSIONSTUDIO_PYTHON; the old override is no longer used.

An unrelated existing fusionstudio command or a modified/incomplete managed block causes preflight to stop instead of replacing it. The installer displays absolute input/output/profile/backup paths before writes, then 1/4 validate environment → 2/4 preflight → 3/4 install → 4/4 verify. A failure during writes can leave completed steps in place; the output identifies backups for recovery. See scripts/README.md for the operation flow.

The renamed Linux launcher and migration passed 69 checks on 2026-10-22 in Kali WSL2, using isolated HOME directories under the project. Checks include all four Bash/Zsh startup modes, repeat installation, exact profile preservation/backups, quoted paths, .venv-linux fallback, argument forwarding, legacy removal, unrelated entries/symlinks, command conflicts and retention of the old wrapper when final verification fails. This run did not open a GUI or change personal shell profiles. See the current command/migration report.

Historical evidence before the command rename: verified on Kali WSL2 on 2026-10-20: 43 command-setup assertions passed, covering Bash/Zsh interactive and login shells, exact profile backups, repeat setup, conflict refusal, missing-environment preflight, spaces/Unicode/apostrophes in paths, and a real WSLg GUI smoke launch through bare ttpselecter from /tmp. The current Kali account was also configured and checked in fresh Bash/Zsh shells. See the command-setup results and GUI preview. These installer checks supplement the separate 31-program application suite.

Linux GUI Troubleshooting and Verification#

  • WSLg normally supplies DISPLAY, WAYLAND_DISPLAY and XDG_RUNTIME_DIR. A remote terminal or headless server needs a graphical session for visible windows; QT_QPA_PLATFORM=offscreen is only for automated checks.
  • If you previously used offscreen checks, run unset QT_QPA_PLATFORM before opening a visible window. QT_QPA_PLATFORM=xcb bash start-fusionstudio.sh explicitly selects X11/WSLg when diagnosing backend issues.
  • Check that you are using Linux .venv/bin/python, rather than a Windows python.exe inherited through WSL's PATH.
  • The Windows setup-fusionstudio.cmd and .ps1 registration scripts do not configure Linux shells. Use bash setup-fusionstudio.sh inside Linux.
  • External MITRE/GitHub links require a configured system browser and desktop URL-opening tools. This minimal WSL test environment did not have a default browser, so external website launch is outside the verified scope; internal Manual feature links were tested separately.

To run the built-in GUI smoke check with a screenshot, from the project folder:

bash
mkdir -p artifacts/linux-wsl
QT_QPA_PLATFORM=xcb bash start-fusionstudio.sh --smoke-test --no-session \
  --screenshot "$PWD/artifacts/linux-wsl/startup-xcb.png"

For broader regression checks, use a disposable Linux checkout and .venv/bin/python -B scripts/audit_linux.py. It prints every absolute input/output, runs 31 existing feature-audit programs with progress, captures individual logs and writes artifacts/linux-wsl/offscreen/audit.json. Real WSLg file pickers and manual links can be exercised with .venv/bin/python -B scripts/audit_linux.py --platform xcb --only audit_manual_language.py. Historical tests need the cached releases documented in scripts/README.md. The runner returns nonzero for failures/timeouts/tracebacks and checks that official data pointers are preserved.

Audit maintenance in this directory: document-export checks compare the version of their actual source catalog instead of assuming v19.2; domain-import checks wait for asynchronous document installation before asserting the result. Older feature audits explicitly discard only their generated drafts during final cleanup so a Save/Discard/Cancel prompt cannot stall unattended runs. Dedicated document/session tests continue exercising save, discard, failure and cancellation behavior. These changes affect test cleanup and synchronization, not the application's document protections.

Linux custom-Bundle compatibility: custom_data_dialog.py carries an explicit Path when Browse/cache selects a local file or an absolute native path is entered in the editable source field. custom_data_import.resolve_location resolves that path locally even when the layer came from HTTP, while string references declared by remote layers keep relative/root-relative URL semantics. Changing the source field reclassifies the location and invalidates earlier approval; retrying validation retains the chosen local-file identity. This prevents a POSIX cache path such as /home/.../custom/<hash>.json from being sent as an HTTP path. The existing source-validation stages still print the absolute local input and cache output and verify content hashes before acceptance. audit_custom_data_url.py covers local selection with a remote origin and preservation of remote-relative URL behavior.

Set Up the fusionstudio Command (Windows PowerShell and cmd)#

After completing Installation above, double-click setup-fusionstudio.cmd in the extracted project folder. It detects that folder automatically; there is no fixed drive or username to edit. The setup window displays its progress and waits for Enter before closing, including when setup fails.

You can also run it from PowerShell:

powershell
.\setup-fusionstudio.cmd

Or from cmd:

cmd
setup-fusionstudio.cmd

Close and reopen PowerShell or cmd after setup; if you use Windows Terminal, close all its windows and reopen it. From any directory, run:

text
fusionstudio

No environment activation is needed. To verify paths and dependencies without opening the application, run fusionstudio -Check in either shell. The old ttpselecter and ttpselector Windows commands are no longer provided. If this project directory is already registered in your user PATH, the new command works without rerunning setup. Setup registers commands only; complete the Python/dependency/data installation first. Keep the extracted project folder in place because the command uses its .venv and files. To move it, remove the old project directory from your user Path in Windows Environment Variables, then rerun setup in the new folder.

Setup modifies only the current user's Windows Path, preserving existing entries and avoiding duplicates when repeated; administrator access is not required. It does not edit PowerShell profiles or persistent execution policy. For noninteractive setup, run powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Install-FusionStudioCommand.ps1. The policy override applies only to that process.

Workflow: setup-fusionstudio.cmd invokes scripts/Install-FusionStudioCommand.ps1, which prints absolute input paths and the output registry setting before 1/4 validate project → 2/4 check environment → 3/4 register user PATH → 4/4 verify. Setup creates no files and opens no application window; failed preflight checks leave Path unchanged. fusionstudio.cmd invokes scripts/Start-FusionStudio.ps1, which prints absolute program/Python/dataset/settings/session and log paths before 1/3 validate → 2/3 launch → 3/3 launch requested. The launcher starts .venv\Scripts\pythonw.exe -B main.py in the project directory and writes separate timestamped logs under artifacts\launch. Language settings and workspace recovery work as with a normal launch. See scripts/README.md for implementation and failure handling.

Current User Workflow#

  1. Launch the application and review the absolute catalog input paths and loading progress.
  2. Browse the document's Platform → Tactic → Technique tree or search by ID/name. New files use Enterprise; right-click the filename and choose ATT&CK Domain to select Mobile or ICS. Use Open ATT&CK Matrix in the TTP sidebar to browse the right-side tactic matrix for that domain.
  3. Inspect descriptions, the complete sub-technique family, Procedure Examples, and reference links in the independent Technique Details tab; copy a title or description when needed. Close its × or right-click → Close Details. Click a TTP or View → Technique Details to reopen it.
  4. Use File → New File or Ctrl+N to create another empty document. Check or uncheck techniques and review that document in Selected Techniques.
  5. Browse the ATT&CK, ATLAS and CAR libraries using their supported categories, filters and search controls.
  6. Open Version to refresh the official release list or change the active document's snapshot. Other documents retain their own snapshots.
  7. Use File → Save / Save As for complete Studio documents. Use File → Export, Ctrl+Shift+E, or the selected-content export button for supported exchange/report formats. Choose the file location and content scope; partial or exchange exports do not establish a complete saved baseline.
