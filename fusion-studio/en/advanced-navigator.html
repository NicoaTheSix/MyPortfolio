Advanced Navigator Workflows#

Matrix presentation#

Independent Show names / Show IDs, Tactic background / Header color…, Expand annotated, colored annotation underlines and read-only source Notes are explained in the matrix display guide. These use standard layer fields and do not change selected TTPs.

Open the matrix from the TTP sidebar. Choose Flat, Side or Mini beside Platform. Flat uses an expandable vertical family tree; Side places parents beside their child lists; Mini groups compact technique squares with their parent. Click to select, double-click for details, hover for names/scores/annotations and right-click for technique actions. Use the small arrow or Expand/Collapse all for children.

Choose Name ↑ / ↓ or Score ↑ / ↓. Score sorting uses the displayed family aggregate when enabled, otherwise the technique score; missing scores count as zero. Sorting changes display order, not scores or selected TTPs. Use Multiple… / Platforms (…)… to check several platforms. They form a union; unchecking all shows an empty matrix. The ordinary Platform dropdown is a shortcut for one platform or all platforms. Search combines with platform filters. Cross-tactic/family preferences, Description/Data Sources fields and Mitigation add/remove are described in the selection/search guide.

Layout, sorting and platform choices belong to the active layer and are saved in Navigator JSON (layout.layout, sorting, filters.platforms) and the full layer in Studio JSON. Switching layers restores those settings. Imported unknown platform names remain in the JSON but have no matching matrix cells. Show all layers only combines layers using the same domain, release and dataset identity.

In the all-layer color view, score ordering still uses the active layer's scores/aggregates; color mixing does not create a combined score.

SVG follows the selected layout, platform union, search, sorting and colors. Advanced settings add units/dimensions/font/header/legend/borders, all/expanded/no children and an in-memory preview. Single-layer Excel keeps a labeled vertical matrix plus Techniques/Layer Info; Export all open layers to Excel… creates one sheet per layer using each layer's saved filters. Excel does not imitate Mini squares or Side columns. See Aggregation and Matrix Exports.

Links and Metadata#

For independent Enable/Disable controls and multi-technique annotation editing, see Independent States and Batch Operations. Export inclusion and enabled state are separate; inclusion no longer generates a default blue color.

Right-click a technique and choose Edit technique annotation…. Choose its tactic scope, then use the Links and Metadata tabs. Links have a label and URL; Metadata has a name and text value. Add/remove rows or dividers, then Save. Save each scope before switching scopes; Cancel discards the current draft. The Include checkbox controls TTP selection separately from annotations.

For example, attach a link labeled Investigation to https://example.org/case/123, and metadata Owner = Detection team, Confidence = High. Metadata is visible in technique hover text. Safe HTTP(S) links appear as Open: … in the context menu. New or changed links require absolute HTTP(S) URLs without embedded credentials. Other protocols already present in imported data are retained but not opened by this app.

Use Layer settings… → Layer links / Layer metadata for layer-level entries. Save updates the layer atomically; invalid entries leave it unchanged. Existing entry extensions and dividers are retained. The app's reserved selection metadata is maintained automatically and excluded from the technique editor. Navigator JSON and Studio JSON preserve full global/scoped annotations, links, metadata and extension fields. CSV remains a selected-TTP report with comments and dataset provenance; use JSON for full structured layer data.

URL layers and custom STIX#

Choose File → Load layer URL / custom STIX…. For a Navigator URL, paste a direct HTTP(S) JSON URL and press Load and validate preview. Open continues to the Navigator import preview, where you check all or selected layers, choose each layer's selection policy and resolve its recorded ATT&CK release. Every checked layer must be ready before the whole group opens. See multi-layer JSON opening. A website HTML page is not a layer JSON file.

For custom data, choose Custom STIX Bundle / Collection, paste a URL or Browse to a JSON file. An ATT&CK Collection Index lists its versions; choose one, then press Load again to fetch that exact Bundle. A Bundle containing x-mitre-collection is accepted directly. A standalone collection object with only references must be supplied together with its referenced objects in a Bundle. This is an ATT&CK-compatible catalog loader, not a general-purpose STIX viewer.

Bundles need active techniques with unique domain-specific external IDs, names, valid domain kill-chain phases, x-mitre-tactic, x-mitre-matrix, and consistent x_mitre_domains. Official defaults use T#### / T####.###; custom domain definitions separate display name, chain and ID source and allow bounded IDs such as LAB-001.child. Multiple matrices use an ordered tactic union, preserving later columns. Sub-techniques need an active single-level parent through an explicit scoped relationship. Latest STIX object versions are chosen by modified; conflicting duplicates, invalid fields and ambiguous IDs fail before a document opens. Collection release metadata takes precedence; otherwise supply a numeric fallback release. Choose an available domain in the preview, then Open as a new document. A loadable example is included in examples.

Operations show the resolved absolute input file or source URL and cache directory before processing, followed by read/parse/validate/cache stages. Validated bytes are atomically cached at <project-root>/data/attack/custom/<sha256>.json; official snapshots and active.json/latest.json are preserved. Navigator inputs are limited to 10 MiB / 20 layers; custom data to 128 MiB / 200,000 objects. HTTP(S) requests have a 20-second socket timeout; redirects must remain HTTP(S). Cancel requests stop at processing checkpoints; errors do not install a partial document.

Custom documents record source and SHA-256 identity in Studio JSON; CSV includes source/hash columns; Navigator JSON includes customDataURL and x_ttp_studio_dataset. Local sources are absolute local paths, so their Navigator layers are portable together with the Bundle: load the same Bundle or supply its exact hash-verified cache on another machine. Only web URLs are directly usable by the official browser Navigator. A custom layer never silently resolves against same-version official data. Exact loaded catalogs and verified Bundle caches resolve offline. Missing or ambiguous sources can now be supplied with Resolve custom data… inside the layer import preview, including explicit URL fetch, local Bundle/cache choice and Collection Index selection. Domain/release/hash validation occurs before acceptance; changed hashes require explicit replacement consent. Relative remote references use the final layer URL after redirects; embedded URLs are not fetched automatically. See the customDataURL guide. Official release switching is offered on official files; load another custom dataset separately or migrate through the review workflow. Ctrl+N always creates an official Enterprise document.

Reviewed layer upgrades#

Choose Navigator → Review and upgrade layer…. Select a cached official release, or an open custom dataset in the same domain. To make a different official release available, download it with Version on an official document first. Press Load target and compare. Technique review lists the complete Added/Changed/Removed/Replaced/Unchanged comparison, including unannotated techniques. Annotation mappings lists all source annotation rows and selected unannotated TTPs; hover a source ID for the original annotation. Category/annotated/pending filters leave full counts and completion requirements unchanged. Added items can be annotated through Annotate added target… before completion and stay unselected unless explicitly included. See the complete review guide.

Unchanged mappings start reviewed. Changed techniques, removed tactic scopes, unavailable IDs and replacements require review. Replacement suggestions use explicit STIX revoked-by relationships; unavailable/deprecated IDs without that relationship have no guessed replacement. Choose Copy, a searchable target technique and target tactic (or All tactics), then mark Reviewed. Drop explicitly omits that source annotation row. Show only rows requiring review and Mark visible decisions reviewed help review larger layers; creation still validates every decision.

Select a source row to inspect complete before/after records and annotations side by side in Content comparison. The paired panes include names, descriptions, tactic mappings and full STIX/extensions; Raw differences retains field changes and original annotation JSON. Each official side offers a checked major-version website link without latest-page fallback. Choose a valid Copy target/scope and Edit target annotation… to revise its fields before migration; editing requires review again. See the content/editing guide for archive limitations, clearing fields, independent target drafts and preservation.

Example: a revoked source ID contains comment = Lab observation, a score, color, links and metadata. Copy it to the suggested replacement after checking its meaning and choose a valid target tactic. The new layer receives those annotations and selection status. When multiple rows map to one target scope, compatible data combines, distinct comments are retained and link/metadata duplicates are removed. Conflicting scalar values such as two different scores/colors/enable flags require explicit review: choose a candidate/custom/clear action in Review migration conflicts…, or remap/Drop a source row. A removed tactic never silently becomes All tactics.

Review final summary… → Submit migration requires all rows to be reviewed and all Copy targets/scopes valid. A new tab uses the target catalog/version; the original file stays unchanged. The source layer is archived in the result, and x_ttp_studio_upgrade records each decision. Progress covers comparison, mapping and completion. The document remains in memory until Save/Export; automatic session checkpoints can also preserve the draft. Studio JSON preserves the archive; Navigator JSON preserves the migrated layer and decisions. Use Save/Save As to persist the complete Studio document, including archives. Studio JSON reopening and session recovery are described in the file/recovery guide.

See the project README for startup and audit commands, and the official Navigator layer format for exchange fields.

Custom release numbers identify that dataset's own release: modern custom STIX with version 1.0 still supports Navigator operations. The pre-v4 restriction concerns historical official ATT&CK data. Migration source archives are written under migration_archives in Studio JSON with their source domain/version/dataset identity; they cannot automatically restore into a different dataset through Version switching.

Final submission now passes through the complete summary, optional skip reasons and unfinished-item navigation.
